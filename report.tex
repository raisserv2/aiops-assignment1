\section{Technical Debt Diagnosis}

\textbf{(a) Entanglement (CACE):} Modifying the delivery-time feature's rounding logic unexpectedly degraded the unrelated favorite-restaurants feature. In ML models, the weight matrix couples all input features together, so changing one feature's preprocessing shifts behavior on unrelated outputs.

\textbf{(b) Undeclared Consumers:} The marketing team was silently reading the model's raw output table without the ML team knowing. This creates an invisible dependency. Any change to the output schema or score distribution by the ML team would break marketing's pipeline without warning.

\textbf{(c) Glue-Code Debt (Pipeline Jungle):} 14 undocumented shell scripts with no orchestration. No parameterization, no reproducibility, and tribal knowledge is needed to run it.

\textbf{Mitigation for (c):} Replace the scripts with an MLflow Project. An \texttt{MLproject} file defines named entry points with declared parameters and types, and a \texttt{python\_env.yaml} pins dependencies. The pipeline becomes runnable via \texttt{mlflow run .\ -P lr=0.01}, and each run is auto-tracked in MLflow.

\section{MLflow Experiment Comparison}

Six experiments trained a two-layer MLP (\texttt{MLPClassifier}) on MNIST, varying learning rate and hidden layer sizes. All runs used \texttt{batch\_size=200}, \texttt{seed=42}, and 20 epochs.

\textbf{Best run:} \texttt{lr=0.001} with hidden layers \texttt{(256, 128)} at 97.51\% accuracy. Larger network with a moderate learning rate gave the best test performance.

\textbf{Overfitting:} Train loss dropped from 0.39 to 0.01 over 20 epochs, but validation accuracy flattened around epoch 5 at about 96.6\% and barely moved after that. The model kept fitting the training data without improving on unseen data.

\textbf{Hyperparameter effect:} Learning rate had a bigger impact than architecture. Holding hidden layers at (128, 64), changing lr from 0.001 to 0.0001 dropped accuracy by about 1\%. Architecture changes across the same lr showed a similar range but the change was more gradual.

\section{DVC Data Versioning and Rollback}

DVC tracked a CSV of image filenames. v1 had 1800 rows; after appending new entries, v2 had 2801 rows. Both versions were pushed to an SSH remote. To roll back, I ran \texttt{git checkout v1} then \texttt{dvc checkout}, which restored the file to exactly 1800 rows (\texttt{wc -l}: 1801 with header). Going back to \texttt{master} and running \texttt{dvc checkout} again restored v2 (\texttt{wc -l}: 2802). This shows DVC correctly restores data when the \texttt{.dvc} pointer file is reverted.

\section{End-to-End Reproducibility}

\textbf{Partner A:} Trained an MLP on DVC-tracked MNIST data. Logged all params (lr, hidden layers, epochs, batch size, seed), the final accuracy (0.9782), and a \texttt{git\_commit} tag in MLflow. Code and \texttt{.dvc} file were committed together. The model was registered as \texttt{my-classifier} and moved to Staging.

\textbf{Partner B:} Cloned the repo, set up the env from \texttt{environment.yml}, pulled data via DVC SSH remote, and re-ran training. Got 0.9784 accuracy (diff of 0.0002 from Partner A's 0.9782, well within the 0.005 tolerance). The small difference comes from floating-point behavior on different hardware. A reproducibility note was logged in MLflow confirming the match.

The full protocol (Git + DVC + MLflow + pinned environment) worked as expected for independent reproduction.
